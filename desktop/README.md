# Глина за компютър (Windows и Linux)

Тази папка прави настолно приложение от офлайн версията на Глина. Приложението е един прозорец
(Electron), който отваря `dist/glina.html` — същия файл, който се сглобява от `../index.html`.
Тук няма отделно копие на кода на приложението: при всяко сглобяване `dist/glina.html` се копира наново.

Готовото приложение **не използва интернет**. Интернет трябва само докато се сглобява
(npm, Electron и инструментите на electron-builder се свалят от npm и GitHub).

## Какво се получава

| Файл | Система | За какво е |
|---|---|---|
| `Glina-Setup-<версия>-x64.exe` | Windows 10/11, 64 бита | Инсталатор на български (няколко редки съобщения на electron-builder, например „Glina is running. Click OK to close it.“ при обновяване, остават на английски). Инсталира само за текущия потребител (без администраторски права), пита в коя папка, прави пряк път „Глина“ на работния плот и в менюто „Старт“. Премахва се от „Настройки → Приложения“. |
| `Glina-<версия>-x64-portable.exe` | Windows 10/11, 64 бита | Без инсталиране: просто се стартира (например от флашка). При всяко пускане се разархивира във временна папка, затова тръгва по-бавно. |
| `Glina-<версия>-x64-win.zip` | Windows 10/11, 64 бита | Само когато Windows версията е сглобена на Linux (вижте по-долу): разархивирайте и пуснете `Glina.exe`. |
| `Glina-<версия>-x86_64.AppImage` | Linux, 64 бита (всяка дистрибуция) | Един файл: `chmod +x Glina-*.AppImage` и го стартирайте. |
| `glina_<версия>_amd64.deb` | Debian, Ubuntu, Mint и др. | Инсталира се в `/opt/Glina`, добавя „Глина“ в менюто (раздел „Графика“) и командата `glina`. |

Къде са файловете:

- при сглобяване на компютъра: в `desktop/out/`;
- в GitHub: всяко качване в `main` пуска `.github/workflows/desktop.yml`; файловете са в раздела
  **Actions** като `glina-desktop-linux` и `glina-desktop-windows`;
- издание (Release) с всички файлове: качете промяната в клона `release` (`git push origin main:release`).
  `.github/workflows/release.yml` сглобява уеб, Windows, Linux и Android версиите и създава етикета
  `v<версия>` и изданието. Вече издадена версия се отказва: първо вдигнете версията.

Размери на версия 1.0.0 от GitHub: инсталатор 111 MB, portable.exe 111 MB, AppImage 123 MB, deb 98 MB.

## Сглобяване

Нужен е Node.js 22.12 или по-нов.

```sh
cd build && npm ci && node build.mjs   # 1. офлайн файлът dist/glina.html
cd ../desktop && npm ci                # 2. Electron и electron-builder (точни версии от package-lock.json)

npm run dist:linux                     # на Linux:   AppImage + deb
npm run dist:win                       # на Windows: инсталатор + portable.exe
npm run dist:win-from-linux            # на Linux:   portable.exe + zip за Windows

npm start                              # пуска приложението направо, без пакетиране
```

Всяка от командите `dist:*` първо пуска `scripts/prepare-app.mjs`, който копира `../dist/glina.html`
и иконата в `app/` (и иконата в `icons/`). Ако `index.html` е по-нов от `dist/glina.html`,
скриптът предупреждава: пуснете отново `node build.mjs` в `build/`.

Версията на всички платформи се задава в `build/package.json`. GitHub Actions я подава на
electron-builder (`-c.extraMetadata.version`), а при етикет `v1.2.3` взима `1.2.3`. При сглобяване на
компютъра се използва `"version"` от `desktop/package.json`, затова я дръжте същата.

### Windows, сглобен на Linux

- **portable.exe и zip** се правят без Wine. electron-builder слага иконата и данните за версията в
  `Glina.exe` със собствен JavaScript код (resedit), така че и те имат иконата на Глина.
- **Инсталаторът (NSIS) на Linux изисква Wine**: electron-builder сглобява помощна програма и я пуска
  под Wine, за да получи програмата за премахване (uninstaller). Тук Wine няма, а собственият пакет
  Wine 11 на electron-builder (`toolsets.wine: 1.0.1`, бета) се сваля, но не тръгва
  (липсват му Windows библиотеките, грешка `c0000135`). Затова инсталаторът се сглобява от GitHub
  Actions на `windows-latest` или на компютър с Windows (`npm run dist:win`). Ако на вашия Linux има
  Wine с поддръжка на 32-битови програми: `npx electron-builder --win nsis --x64 --publish never`.
- Програмите не са подписани с код-сертификат, затова Windows SmartScreen може да покаже
  предупреждение при първото пускане: изберете „Още информация“ (More info) → „Изпълни въпреки това“
  (Run anyway).

## Проверка

```sh
xvfb-run -a node test/smoke.mjs              # пакетираната версия в out/linux-unpacked/
xvfb-run -a node test/smoke.mjs --dev        # `electron .` (след npm run prepare-app)
xvfb-run -a node test/smoke.mjs --exe ПЪТ    # друга сглобка, напр. glina от разопакован .deb
```

Тестът пуска приложението без екран и проверява: страницата се зарежда без нито една мрежова заявка
(по журнала на Chromium: 0 DNS заявки, 0 връзки), прозорецът е 1400×900 със заглавие „Глина“ и без
меню, моделът се рисува (и след загубен и възстановен WebGL контекст), щрих с писалка
(`pointerType: "pen"` с натиск) променя модела и по-силният натиск го променя повече, Ctrl+Z връща
модела, износът на OBJ минава през прозореца „Запазване“ в „Документи“ с име `glina-model.obj`,
F11 включва и изключва цял екран, отказани са изскачащи прозорци, напускане на страницата, достъп до
камера, местоположение и известия, автоматичният запис оцелява след рестарт, второ стартиране само
показва вече отворения прозорец, и няма грешки в конзолата.

На машина без видеокарта (контейнер, CI) тестът добавя `--disable-gpu`: там първият GPU процес на
Chromium не тръгва и Chromium го пуска наново в софтуерен режим, при което първият WebGL контекст на
страницата се губи. Приложението се възстановява само, но three.js записва грешка в конзолата.
`GLINA_TEST_GPU=1` пуска теста с настройките на самото приложение.

## Файловете в тази папка

| Файл | Какво прави |
|---|---|
| `main.js` | Главният процес: прозорецът, защитата, прозорецът „Запазване“, F11. |
| `package.json` | Точните версии (Electron 44.6.0, electron-builder 26.17.0, playwright-core 1.56.1 за теста), командите и настройките на electron-builder. |
| `package-lock.json` | Заключените версии на всички зависимости (`npm ci`). |
| `scripts/prepare-app.mjs` | Копира `../dist/glina.html` и иконата в `app/` и `icons/` преди сглобяване. |
| `resources/installer.nsh` | Добавки към инсталатора: само за текущия потребител и българските текстове, които липсват в NSIS. |
| `test/smoke.mjs` | Тестът по-горе. |
| `app/`, `icons/`, `out/` | Създават се при сглобяване; не са в git. |

Иконата е `build/icons/icon-1024.png`. За Linux от нея се правят размери от 16 до 512 px
(1024 px не се търси от темата на иконите), за Windows — `.ico` файл.

## Писалка и натиск по системи

Натискът стига до приложението като стандартни Pointer Events (`pointerType: "pen"`, `pressure` от 0
до 1). Electron 44 (Chromium 152) не иска допълнителни настройки за това.

- **Windows 10/11** — чрез Windows Ink, по подразбиране. При Wacom в „Wacom Tablet Properties“
  оставете включено „Use Windows Ink“ (включено е по подразбиране). При Huion, XP-Pen и др. включете
  „Windows Ink“ в драйвера на таблета.
- **Linux с X11 (Xorg)** — чрез XInput2. Устройство с ос „Abs Pressure“ (драйвер `xf86-input-wacom`
  или `libinput`) се отчита като писалка с натиск. Проверка: `xinput list`, после
  `xinput list-props <номер>`.
- **Linux с Wayland** — от Electron 38 приложението по подразбиране работи като истинско Wayland
  приложение (`--ozone-platform=auto` е подразбиране; старият ключ `--ozone-platform-hint=auto` не е
  нужен). Chromium поддържа протокола за таблети на Wayland (`tablet-unstable-v2`; добавен през 2025 г.,
  има го в Chromium 140 и в Chromium 152 на Electron 44): писалка, гума, натиск и наклон. Нужно е композиторът също да го поддържа (GNOME, KDE Plasma, Sway,
  Hyprland го поддържат). Ако писалката не работи както трябва, пуснете през XWayland:
  `glina --ozone-platform=x11` или `./Glina-*.AppImage --ozone-platform=x11`.

Честно казано: тук натискът е проверен само със синтетични събития на писалка, подадени през входния
път на Chromium (Xvfb, без истински таблет). Поддръжката за X11 и Wayland е проверена по изходния код
на Chromium 152, не с истински таблет. В долната лента на приложението има индикатор „натиск“ —
по него се вижда веднага дали натискът идва.

## Без интернет и защита

- Прозорецът зарежда само `app/glina.html` от пакета. Всяка заявка, която не е към локален файл
  (`http`, `https`, `ws` …), се спира. Изключена е и проверката на правописа, защото на Linux тя би
  свалила речници от интернет при първото пускане.
- Забранени са нови прозорци, напускане на страницата, всички разрешения (камера, микрофон,
  местоположение, известия, USB и др.); страницата няма достъп до Node.js (`contextIsolation`,
  `sandbox`). Няма меню, а с него и клавиши за презареждане и инструменти за разработчици.
- Само едно копие: второ стартиране показва вече отворения прозорец.
- Износ (OBJ, STL): отваря се прозорец „Запазване на модела“ в папка „Документи“ с предложеното име.
- Автоматичният запис и настройките се пазят в профила на приложението: Windows `%APPDATA%\Glina`,
  Linux `~/.config/Glina` (и за portable.exe — не до самия файл).
- Без използваема видеокарта (стар драйвер, виртуална машина) Глина рисува със софтуерния рендер на
  Chromium (SwiftShader): работи, но по-бавно.
- **AppImage**: на Ubuntu 22.04 и по-нови е нужен `libfuse2` (`sudo apt install libfuse2t64` на
  24.04, `libfuse2` на 22.04). На Debian/Ubuntu по-лесно е да инсталирате `.deb` файла. Без `libfuse2`:
  `NO_CLEANUP=1 ./Glina-*.AppImage --appimage-extract-and-run`. Без `NO_CLEANUP=1` второ стартиране
  изтрива файловете на вече отворения прозорец. Пясъчникът (sandbox) на
  Chromium се изключва само ако системата не позволява user namespaces (например Ubuntu 24.04 с
  ограничението на AppArmor); `.deb` пакетът вместо това инсталира AppArmor профил.
